The plan: HTML is nested boxes (a tree), and one set of selectors finds things in it everywhere.

  • Point at the indents on the left: header and form sit inside body; the cards sit inside poke-container. That nesting is the tree.
  • Point at the table: tag, .class, #id. The same strings work in CSS, in querySelector and in Cypress.
  • Say: "The browser turns this HTML into the DOM: a tree of objects JavaScript can change."

  • Read row by row. Point at the yellow React column each time.
  • Rows 1–2: JSX is JavaScript, and class and for already mean something in JavaScript, so React renamed them.
  • Row 3: two braces. The outer {} = "JavaScript here"; the inner {} = the object.

3 · A form sends a submit event. Stop the reload.

const handleSubmit = (event) => {
  event.preventDefault()
  const data = Object.fromEntries(
    new FormData(event.target)
  )
  const name = data.name.trim().toLowerCase()
  if (!name) return
  getPokemonData(name)
  event.target.reset()
}

<form onSubmit={(event) => handleSubmit(event)}>
  • submit, not click: Enter works too
  • preventDefault(): no page reload
  • event.target = the form
  • Each input's name becomes a key: data.name

Same in React This came from the DOM lesson, and it's in our React app now.

The plan: Our real handleSubmit from App.jsx, and the four DOM ideas inside it.

  • Point at preventDefault() (yellow): without it, the browser reloads the page and our cards vanish.
  • Point at new FormData(event.target): event.target is the form. Object.fromEntries turns it into { name: "pikachu" }.
  • Point at onSubmit at the bottom: we listen on the form, not the button, so pressing Enter works too.
  • Say: "This is the event object from the DOM lesson. React passes us the same kind of event."

5 · A component is a function that returns JSX

import './App.css'

function App() {
  let message = "Hello Pokemon trainers"
  const sayHello = () => "Hello from a function"
  return (
    <>
      <h1>Pokemon Project</h1>
      <p className="myText">{message}</p>
      <p>{sayHello()}</p>
    </>
  )
}

export default App
  • The name starts with a Capital: <App />
  • Return one parent: <> </> is a wrapper that adds nothing to the page
  • { } = "JavaScript here": values and calls
  • export it, so main.jsx can put it into <div id="root">

The plan: Our first App.jsx from React + Vite: what makes a function a component.

  • Point at function App(): just a JavaScript function. Capital A, so React knows it's a component and not an HTML tag.
  • Point at return ( <> … </> ): one parent. The empty tags are a Fragment.
  • Point at {message} and {sayHello()}: braces drop JavaScript into the markup. Here we call the function, because we want what it returns.
  • Point at export default: main.jsx imports App and renders it into the root div in index.html.
  • Say: "Every new piece of the app, the card, the form, the pages, will be one of these."

6 · Requests take time, and they can fail

const getPokemonData = async (name) => {
  try {
    const response = await axios.get(
      `https://pokeapi.co/api/v2/pokemon/${name}`
    )
    generateCard(response.data)
  } catch (error) {
    alert("Pokemon Does not Exist")
  } finally {
    console.log("Request completed")
  }
}
  • await waits for the answer. It only works inside an async function
  • The Pokemon is in response.data
  • A bad name (pikachoo) is a 404 → catch
  • finally runs either way

You'll use it in useEffect, the router's Pokemon pages, and the Cypress tests that call the real PokeAPI.

The plan: Our real getPokemonData: the request starts, the page keeps going, and we handle the answer or the error later.

  • Point at async and await: await pauses this function only, not the page.
  • Point at response.data: axios already turned the JSON into an object.
  • Point at catch: a misspelled name returns 404, so axios throws and we tell the user.
  • Say: "Same promise as .then / .catch / .finally. Most code you'll read uses await."
